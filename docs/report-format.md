# פורמט הדוח

זה החוזה בין המשימה המתוזמנת שכותבת את הדוח לבין האפליקציה שמציגה אותו.
כל עוד הקובץ עומד בפורמט הזה, הוא יופיע באפליקציה אחרי הדחיפה ל־GitHub.

## שם ומיקום

- תיקייה: `reports/`
- שם הקובץ: תאריך הפרסום בפורמט `YYYY-MM-DD.md`, לדוגמה `reports/2026-09-25.md`
- שני דוחות באותו יום: מוסיפים סיומת, לדוגמה `2026-09-25-special.md`
- קבצים שמתחילים ב־`_` (טיוטות) ו־`README.md` לא מוצגים
- הקידוד חייב להיות UTF-8

## מבנה

הקובץ מתחיל בבלוק YAML (בין שתי שורות `---`) ואחריו גוף הדוח ב־Markdown.

```markdown
---
title: הפד חתך, השווקים כבר היו שם
date: 2026-09-25
summary: משפט או שניים שמסכמים את השבוע. מופיע בכרטיס הראשי ובארכיון.
mood: 1
tags: [ריבית, פד, בנקים]
markets:
  - name: ת"א 35
    value: "2,961"
    change: "+1.8%"
  - name: S&P 500
    value: "6,712"
    change: "+0.6%"
outlook:
  - תחזית קצרה ראשונה לשבועות הקרובים.
  - תחזית קצרה שנייה.
---

## התמונה הגדולה

גוף הדוח...
```

## השדות

| שדה | חובה | הסבר |
|---|---|---|
| `title` | מומלץ | הכותרת. אם חסר, נלקחת הכותרת הראשונה (`# ...`) מהגוף |
| `date` | לא | ברירת המחדל היא התאריך משם הקובץ |
| `summary` | מומלץ | עד כ־400 תווים. מוצג בכרטיס הראשי, בארכיון ובחיפוש |
| `mood` | מומלץ | מספר שלם בין `-2` (פסימי מאוד) ל־`2` (אופטימי מאוד). מזין את גרף מצב הרוח |
| `tags` | לא | רשימת נושאים קצרים. לחיצה על תגית מחפשת אותה בארכיון |
| `markets` | מומלץ | עד 8 נתוני שוק. בכרטיס הראשי מוצגים 4 הראשונים, אז כדאי לשים את החשובים קודם |
| `outlook` | מומלץ | עד 6 משפטים קצרים של תחזית. מוצגים בתיבה נפרדת בסוף הדוח |

ב־`markets`, שלושת השדות הם `name`, `value` ו־`change`. את `value` ואת `change` כדאי לעטוף במירכאות. הצבע של השינוי (ירוק או אדום) נקבע לפי הסימן בתחילת `change`: `+` עלייה, `-` או `−` ירידה, `0` ללא שינוי.

## גוף הדוח

- כותרות משנה ב־`##`. כותרת `#` בגוף הופכת אוטומטית לכותרת משנה.
- טבלאות Markdown נתמכות, וטבלה רחבה נגללת הצידה בטלפון.
- קישורים חיצוניים נפתחים בחלון חדש.
- HTML מסוכן (סקריפטים, `onerror` וכו') מסונן.
- אם הגוף מתחיל ב־`# ` עם אותה כותרת כמו `title`, היא לא תוצג פעמיים.
- כדי שהדוח ייכנס בעמוד אחד: עד כ־700 מילים.

## מה קורה לדוח שבור

סקריפט הבנייה מדלג על דוח לא תקין ומציג אזהרה בריצה של GitHub Actions, ושאר הארכיון ממשיך לעלות. דוח נחשב לא תקין כאשר:

- שם הקובץ לא בפורמט תאריך, או שהתאריך לא קיים (למשל `2026-02-30`)
- בלוק ה־YAML לא תקין
- `mood` הוא לא מספר
- פריט ב־`markets` בלי `name`
- הקובץ ריק, או שאינו UTF-8

בדיקה מקומית לפני דחיפה:

```
python scripts/build_index.py --strict
```
