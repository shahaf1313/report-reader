# המשימה המתוזמנת

המשימה רצה בכל יום שישי בבוקר, כותבת דוח אחד לתיקייה `reports/`, ודוחפת אותו ל־GitHub. מכאן GitHub Actions בונה את האינדקס ומפרסם את האתר, והדוח מופיע באפליקציה תוך דקה או שתיים.

## הגדרה ב־Claude Desktop

1. לשכפל את המאגר למחשב, ולוודא ש־`git push` עובד בלי סיסמה (מפתח SSH או Git Credential Manager).
2. ליצור משימה מתוזמנת חדשה:
   - תדירות: שבועית, יום שישי, 07:00
   - תיקיית עבודה: תיקיית המאגר
   - הרשאות: חיפוש באינטרנט, קריאה וכתיבה של קבצים, והרצת `git`
3. להדביק את הפרומפט שבהמשך.

המחשב צריך להיות דלוק והאפליקציה פתוחה בזמן הריצה. אם זה לא מתאים, אפשר להריץ את אותו הפרומפט כמשימה בענן (Claude Code routine) שמחוברת למאגר.

## ריצה בענן דרך GitHub Actions (מומלץ)

הקובץ `.github/workflows/weekly-report.yml` מריץ את אותו הפרומפט בשרתים של GitHub בכל יום שישי בבוקר, כך שהמחשב לא צריך להיות דלוק. הגדרה חד־פעמית: להריץ במחשב `claude setup-token`, ולהוסיף את האסימון כ־secret בשם `CLAUDE_CODE_OAUTH_TOKEN` במאגר (Settings ← Secrets and variables ← Actions). אם הדוח של היום כבר קיים, הריצה מדלגת. אפשר להריץ ידנית מלשונית Actions (Run workflow).

## הפרומפט

```text
אתה כותב את "הדוח השבועי": סיכום בעברית של השבוע החולף בכלכלה ובשוק ההון,
לקורא ישראלי שמבין בשווקים ומשקיע באופן אישי. היום יום שישי בבוקר, שעון
ישראל. הדוח הוא תקציר עיתונאי, לא ייעוץ השקעות.

0. הכנה.
   - הרץ git pull --rebase כדי לעבוד על הגרסה העדכנית של המאגר.
   - קבע את התאריך של היום (YYYY-MM-DD, שעון ישראל). זה שם הקובץ.
   - אם reports/<התאריך>.md כבר קיים, אל תדרוס אותו: כתוב ל־<התאריך>-2.md
     ודווח על כך בסוף.
   - קרא את הדוח הקודם בתיקייה reports/ (הקובץ עם התאריך המאוחר ביותר).
     שים לב לנתונים שב־markets, לתגיות ולתחזיות שב־outlook. תשתמש בהם
     בהמשך לשמירה על רצף ולבדיקת התחזיות.

1. טווח הזמן. השבוע המדווח הוא מסגירת המסחר של יום חמישי שעבר ועד סגירת
   המסחר של אתמול (יום חמישי). בשעה הזו בורסת תל אביב עוד לא פתחה את
   המסחר של יום שישי, ווול סטריט סגרה לאחרונה ביום חמישי. כל שינוי שבועי
   ב־markets מחושב בין שתי הסגירות האלה. אם לנכס אין סגירה ביום חמישי
   (חג, מסחר רציף), השתמש במחיר העדכני ביותר וציין זאת בגוף הדוח.

2. מחקר. חפש באינטרנט את האירועים והנתונים של השבוע:
   - ישראל: ת"א 35, ת"א 125, ת"א בנקים, דולר/שקל, אירו/שקל, ריבית בנק
     ישראל, מדד המחירים לצרכן, תשואות אג"ח ממשלתיות, נתוני הלמ"ס, תקציב
     וגירעון, דירוג אשראי.
   - ארה"ב: S&P 500, נאסד"ק, הפד, תשואת 10 שנים, תעסוקה, אינפלציה,
     צמיחה.
   - עולם: אירופה והבנק המרכזי האירופי, סין, יפן, נפט ברנט, זהב, ביטקוין.
   - חברות: דוחות כספיים, הנפקות, מיזוגים ורכישות, בעיקר של חברות
     ישראליות ושל ענקיות הטכנולוגיה.
   - יומן: אירועים מתוכננים לשבוע הבא (החלטות ריבית, פרסום מדד, דוחות
     גדולים).
   מקורות: רויטרס, בלומברג, FT, CNBC, כלכליסט, גלובס, דה מרקר, אתר הבורסה
   לניירות ערך בתל אביב, בנק ישראל, הלמ"ס, הפד. בדוק כל מספר שנכנס לדוח
   מול שני מקורות לפחות. אם אין נתון מאומת, השמט אותו. לעולם אל תמציא
   מספר, ציטוט או אירוע.

3. בחירת הסיפור. לפני הכתיבה, החלט מהו הסיפור המרכזי של השבוע: האירוע
   שהזיז הכי הרבה כסף או שישפיע הכי הרבה על הקורא הישראלי. הכותרת,
   הסיכום והפסקה הראשונה נבנים סביבו. עדיף לנתח סיפור אחד לעומק מאשר
   לרשום עשרה.

4. כתיבה. צור את הקובץ בדיוק לפי המפרט ב־docs/report-format.md.

   בלוק ה־YAML:
   - title: כותרת עיתונאית של עד 60 תווים, עם זווית ולא רק עובדה
     ("הפד חתך, השווקים כבר היו שם" ולא "הפד הוריד את הריבית").
   - date: התאריך של היום.
   - summary: שני משפטים, עד 300 תווים.
   - mood: מספר שלם, לפי הסולם:
       2  שבוע של עליות רחבות ואופטימיות ברורה
       1  נטייה חיובית, עם עליות מתונות
       0  מעורב או ללא כיוון
       -1 נטייה שלילית, עם ירידות או חשש גובר
       -2 מכירות חדות, משבר או פאניקה
     קבע אותו לפי התמונה הכוללת, עם משקל גבוה יותר לשוק הישראלי.
   - tags: 3 עד 6 נושאים קצרים בעברית. העדף תגיות שכבר הופיעו בדוחות
     קודמים (ריבית, פד, בנקים, אינפלציה, מט"ח, נפט...) כדי שהחיפוש בארכיון
     יעבוד.
   - markets: 4 עד 8 נתונים. ארבעת הראשונים מוצגים בכרטיס הראשי, אז הם
     הכי חשובים. ברירת המחדל לארבעה הראשונים: ת"א 35, S&P 500,
     דולר/שקל, ונתון רביעי שהיה הסיפור של השבוע. השתמש באותם שמות בדיוק
     כמו בדוחות הקודמים ("ת"א 35", "S&P 500", "נאסד"ק", "דולר/שקל",
     "נפט ברנט", "זהב", "ביטקוין", "תשואת 10 שנים ארה"ב").
     value ו־change תמיד במירכאות כפולות. change הוא השינוי השבועי,
     מתחיל ב־+ או ב־− (ואם אין שינוי, "0.0%"). לתשואות אג"ח, change
     בנקודות בסיס, למשל "+12bp". מחירים בדולרים עם $ בהתחלה.
   - outlook: 2 עד 4 משפטים קצרים על השבועות הקרובים, כל אחד קשור לאירוע
     או לנתון מסוים. נסח כהערכות ("עשוי", "צפוי", "המבחן הבא יהיה"), לעולם
     לא כהמלצה לקנות או למכור.
   אם ערך טקסט מכיל נקודתיים או מתחיל במירכאות, עטוף אותו במירכאות בודדות
   כדי שה־YAML יישאר תקין.

   גוף הדוח, 400 עד 700 מילים:
   - "## התמונה הגדולה": שתי פסקאות על הסיפור המרכזי ולמה הוא חשוב.
   - 3 עד 5 סעיפים ב־## לפי מה שקרה השבוע, למשל "מה הזיז את השווקים",
     "ישראל", "בעולם", "חברות", "מאקרו". דלג על סעיף שאין בו חדשות אמיתיות.
   - "## התחזיות מהשבוע שעבר": שורה אחת לכל תחזית מה־outlook של הדוח
     הקודם, עם מה שקרה בפועל. אם אין דוח קודם, דלג על הסעיף.
   - "## השבוע הבא": רשימה קצרה של האירועים המתוכננים, עם יום ותאריך.
   - "## מקורות": 3 עד 8 קישורים לכתבות ולהודעות הרשמיות שעליהן נשען הדוח.
   אפשר טבלה קטנה אחת (למשל מניות בולטות). שמות חברות, מדדים וטיקרים
   באנגלית מותר להשאיר באנגלית. אל תחזור בגוף על המספרים מ־markets בלי
   להוסיף הסבר למה הם זזו. כתוב בעברית טבעית וקולחת, במשפטים קצרים, בלי
   מילים כמו "דרמטי" ו"היסטורי" אלא אם הן נכונות מספרית.

5. בדיקה. הרץ:
       python scripts/build_index.py --strict
   אם יש אזהרה, תקן את הדוח והרץ שוב עד שאין אזהרות. אחר כך קרא את הקובץ
   פעם אחת מההתחלה ובדוק: שכל מספר בגוף תואם למספר ב־markets, שהכותרת עד
   60 תווים, ושאין שאריות באנגלית באמצע משפט עברי שלא לצורך.
   אל תוסיף את reports/index.json ל־git (הוא ב־.gitignore).

6. פרסום. הרץ:
       git add reports/<הקובץ>
       git commit -m "Weekly report <YYYY-MM-DD>"
       git push
   אם הדחיפה נכשלת, הרץ git pull --rebase ונסה פעם אחת נוספת. אל תשתמש
   ב־--force. אם עדיין נכשל, השאר את ה־commit מקומי ודווח.

בסוף, כתוב שורה אחת: שם הקובץ, הכותרת, ה־mood שבחרת, והאם הדחיפה הצליחה.
```

### מה השתנה לעומת הגרסה הקודמת

- טווח זמן מוגדר: השינוי השבועי נמדד מסגירת חמישי לסגירת חמישי, כי בשבע בבוקר של יום שישי הבורסה בתל אביב עוד לא נסחרה.
- סולם מפורש ל־`mood`, כדי שגרף מצב הרוח יהיה עקבי משבוע לשבוע.
- שמות קבועים לנתוני השוק ותגיות חוזרות, כדי שההשוואה והחיפוש בארכיון יעבדו.
- הדוח קורא את הדוח הקודם ובודק מה קרה לתחזיות שלו, ומסיים ביומן של השבוע הבא.
- `git pull` רץ לפני הכתיבה ולא אחריה, והטיפול בכישלון דחיפה מוגדר.
- הנחיות סגנון לכותרת ולכתיבה, ובדיקה עצמית אחרי הרצת הבודק.

## בדיקה ידנית

אפשר להריץ את המשימה פעם אחת ידנית ולבדוק את הדוח לפני שהיא עוברת לריצה שבועית. תצוגה מקומית:

```
python scripts/serve.py
```

ואז לפתוח את `http://localhost:8000`.
